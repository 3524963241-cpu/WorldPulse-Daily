# 前端对接说明（A 同学看这里）

后端（B 同学）负责生成 `data/news.json`，前端直接 `fetch` 这个文件即可，**不需要任何后端接口、不需要 API Key**。

```js
fetch('data/news.json')
  .then(r => r.json())
  .then(data => {
    console.log(data.updated_at);  // 数据更新时间
    console.log(data.news);        // 新闻数组
  });
```

> 默认用**相对路径** `data/news.json`，这样在本地起服务器和线上 GitHub Pages 都能跑通。

## 数据字段

`data/news.json` 顶层字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `updated_at` | string | 数据更新时间，UTC，ISO 8601 格式，如 `2026-10-13T11:20:18Z` |
| `generated_at` | string | 本次生成时间，UTC。**与 `updated_at` 相同**，保留是为了语义清晰（归档索引里也叫这个名），可直接用来和 `archive/index.json` 交叉校验同期 |
| `date_beijing` | string | **本次数据属于哪一天，北京时间**，如 `2026-10-20`。**它等于归档文件名**，前端切日期请用它 |
| `shift` | string | 班次：`am`（北京 08:30 那班）/ `pm`（北京 20:30 那班） |
| `news` | array | 新闻数组，**已按 `heat` 从高到低排序**，**固定 20 条**（后端配额：地缘 5 / 政治 7 / 市场 8，某类不够时由其他类补位） |

> ⚠️ **不要用 `updated_at` 去推日期**。`updated_at` 是 UTC，而归档按北京时间切日，
> 北京时间 00:00–08:00 这一班会被算成前一天。要日期就取 `date_beijing`。
> 老版本数据（2026-10-21 之前生成）没有这三个字段，此时回退用 `digest.date`。

`news` 数组每一项的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | **12 位十六进制字符串**（如 `46ee43f3cce0`），由 URL 哈希生成。**同一条新闻的 id 跨天不变**，可直接做列表 key、收藏、"这条昨天排第几"的对比 |
| `title` | string | 标题。翻译失败时以 `[EN]` 开头，表示这是英文原文 |
| `summary` | string | 摘要，**可能是空字符串**，前端要能处理 |
| `category` | string | 领域，三个取值，见下表 |
| `country` | string \| null | 中文国家/地区名。**未定位到时为 `null`** |
| `city` | string \| null | **中文城市名**（2026-10-21 新增）。只有标题/摘要里明确出现城市时才有值，**多数为 `null`，属正常** |
| `lat` | number \| null | 纬度。有 `city` 时是**城市中心点**，只有 `country` 时是**国家代表点** |
| `lng` | number \| null | 经度。同上 |
| `locate_basis` | string \| null | 这个地点有多可信，**建议用来控制地图点的样式**，见下方说明 |
| `image` | string \| null | **封面图绝对 URL**（2026-10-21 新增）。实测 20/20 都有，但仍要写占位图兜底 |
| `published_at` | string | 发布时间，UTC，ISO 8601 |
| `source` | string | 来源名称，如 `NPR World`、`MarketWatch Top` |
| `url` | string | 原文链接，可直接跳转 |
| `heat` | number | 热度，**0~100 的整数**，数组已按此降序 |

**`locate_basis` 三个取值**（决定地图怎么画）：

| 值 | 含义 | 建议样式 |
|---|---|---|
| `title` | 标题里明确出现地名，最可信 | 正常实心点 |
| `summary` | 标题没写，摘要里出现且没有互相矛盾的地名 | 正常点，或略淡 |
| `source` | **文中没有任何地名**，按"美股市场新闻"推断为美国 | 空心点 / 半透明，鼠标悬停注明"来源推断" |
| `null` | 没定位到，坐标也是 `null` | 不上地图 |

> ⚠️ **别再依赖数组下标当 id 用**（比如 `news[i]` 做 DOM id）。旧版是 `news-001` 这种序号，
> 每天会指向不同新闻；现在改用 `id` 字段，跨天稳定。

## 每日概览 `data/digest.json`（F28 直接用它）

一句话说明：**当日 20 条新闻的结构化小结**，纯规则生成，每句都能点回原文核对。

```js
fetch('data/digest.json').then(r => r.json()).then(d => {
  d.top3;        // 最热三条 [{id, title, heat}]
  d.sections;    // 三个领域各一句中文小结

  // 点击小结里的标题，跳到对应新闻
  const openNews = id => { /* 用 id 在 news 数组里找 */ };
});
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | string | 概览所属日期，**北京时间**，如 `2026-10-18` |
| `updated_at` | string | 与 `news.json` 的 `updated_at` 一致，可用来校验两者是同一期 |
| `total` | number | 条目数，正常为 20 |
| `by_category` | object | 各领域条数 `{geopolitics, politics, markets}` |
| `top3` | array | 最热三条 `[{id, title, heat}]`，`title` 已去掉 `[EN]` 标记 |
| `geo` | object | `{located: 16, countries: 6, top_country: "美国"}`，`located` 是能上地图的条数 |
| `sections` | array | `[{category, count, text}]`，`text` 是**成句的中文**，可直接渲染 |

`sections[].text` 长这样：

> 地缘冲突 5 条，最受关注的是《阿尔伯塔省军事基地发生致命事件后爆发大火》（热度 91），来自 NPR World。其余报道来自 CNBC World News。

三个注意点：

1. **`text` 可能是空字符串**——某领域当天 0 条时留空，遇到空串**不要渲染那一段**（不要显示"暂无"占位，直接跳过）；
2. **不要把这段叫"AI 助手"**。它是规则生成的客观汇总，标成 AI 会让人以为能追问、能分析，反而露怯。
   写「今日概览」「数据小结」更贴合事实；
3. `top3[].title` 已经去掉 `[EN]`，但 `news[].title` 保留原样——判断翻译状态看 `news`，展示用 `digest`。

## 历史归档 `data/archive/`（F29 历史回看）

```
data/archive/
  index.json              索引，先读这个
  2026-10-18.json         那天最终 20 条
  2026-10-18-digest.json  那天的概览
  2026-10-18-pm.json      班次快照（am 早班 / pm 晚班）
```

`index.json` 结构（**按日期倒序**，最新的在前）：

```json
{
  "dates": [
    {"date": "2026-10-18", "count": 20, "generated_at": "2026-10-18T08:48:01Z", "has_digest": true},
    {"date": "2026-10-17", "count": 20, "generated_at": "2026-10-17T12:31:05Z", "has_digest": true}
  ]
}
```

用法：

```js
// 日期选择器：直接用 dates 渲染
const { dates } = await fetch('data/archive/index.json').then(r => r.json());


// 点某一天，加载那天的新闻（结构和 news.json 完全一样，只是 updated_at 是那天的时间）
const day = await fetch(`data/archive/${dates[0].date}.json`).then(r => r.json());
```

- 归档保留最近 **90 天**，更早的会被 B 自动清理；
- 归档日期按**北京时间**划分，所以 `2026-10-18.json` 指北京时间 10 月 18 日全天；
- **归档文件我这边可能还没生成**（首次部署后才开始累积）。前端要能处理「`index.json` 不存在 / `dates` 为空」的情况，
  不要写成一旦请求失败整个页面就白屏。建议 `try/catch` 后隐藏历史模块。

### 三个协议问题的明确答复

**1. `has_digest: true` 是否保证 `xxx-digest.json` 一定存在？**

保证。写入顺序是「先写概览文件，成功了才把 `has_digest` 置 true」，因此
`has_digest: true` → 文件必然存在；`has_digest: false` → 文件必然不存在。
但**仍建议前端 catch 住 404**：90 天后清理时，索引和文件是同一批删的，
理论上有极短的中间态。

**2. 日期按 UTC 还是北京时间？**

**北京时间**。`2026-10-20.json` = 北京时间 10 月 20 日这一整天。
但它和 `news.json.updated_at` 的口径不同（后者是 UTC），北京时间
00:00–08:00 这一班两者会差一天。为此我在 `news.json` 顶层加了
`date_beijing` 字段，**它恒等于归档文件名**，直接用这个就不会错：

```js
const cur = news.date_beijing;              // 2026-10-20
const isArchive = d => d.date === cur;
```

**3. `geo.located` 到底指什么？**

指「有坐标的条数」。同时新增了 `has_country` 和 `has_city` 两个字段把话说死：

```json
"geo": {
  "located": 20,        // 有坐标（可上地图）
  "has_country": 20,    // 有国家名
  "has_city": 0,        // 有城市名（更精确）
  "countries": 13,      // 涉及多少个国家/地区
  "top_country": "美国",
  "cities": [{"city": "伦敦", "count": 1}]   // 新增：城市分布
}
```

正常情况 `located == has_country >= has_city`。当前 `has_city` 通常是 0 或个位数，
**不是 bug**——实测 100 条原始新闻里，标题含城市名的只有 1 条
（NPR/CNBC 写的是"某国内部发生了什么"，几乎不点城市名）。
城市表已备好 121 个城市，等新闻本身带出城市名时会自动生效。

### `digest.json` 新增 `paragraphs`（P2）

主推的「今日概览」正文可以直接用它，不必自己拼句子：

```js
d.paragraphs.forEach(p => {
  // 每段都是完整中文句子，形如：
  // "本期共收录 20 条国际新闻，来自 3 个来源。"
  // "地理上看，美国出现最多，共 5 条；13 个国家/地区被提及。"
  renderParagraph(p);
});
```

纯模板拼接，**每一句都能回溯到具体条目**，不含判断和预测。
嫌长可以只取前 3 段；不用这个字段也不影响任何现有功能。


### `category` 三个取值

| 值 | 含义 | 建议配色 |
|---|---|---|
| `geopolitics` | 地缘冲突 | 红 |
| `politics` | 国际政治 | 蓝 |
| `markets` | 金融市场 | 绿 |

const CATEGORY_LABEL = {

## ⚠️ 地图功能必读

**`lat` / `lng` 为 `null` 的新闻，请不要在地图上打点**，只在列表里显示。

原因是宁缺毋滥：定位不到的新闻如果随手扔个坐标上去，地图上就会出现错误的点，反而是硬伤。

判断方式：

```js
news.filter(n => n.lat !== null && n.lng !== null)  // 这批才能上地图
```

### 城市级 vs 国家级：zoom 不一样

拿到 `city` 就用城市坐标把地图飞近，只有 `country` 就用国家代表点：

```js
function flyTo(item, map) {
  const zoom = item.city ? 9 : 6;      // 城市 zoom 9，国家 zoom 6
  map.flyTo([item.lat, item.lng], zoom);
}
```

点国家 → 面板列出该国条目 → 点条目：**如果那条有 `city`，地图会飞到 zoom 9；
如果还停在 zoom 6，说明这条没有城市字段**，不是前端没读到。

`has_city` 当前多为 0 或个位数，**这是数据特性不是 bug**：实测 100 条原始新闻里
标题含城市名的只有 1 条（NPR/CNBC 讲的是"某国内部发生了什么"，几乎不点城市名）。
词典已备好 121 个城市，新闻自己带出城市名时会自动生效。

### 地点可信度：用 `locate_basis` 区分

| `locate_basis` | 含义 | 建议 |
|---|---|---|
| `title` | 标题里明写了地名 | 实心点 |
| `summary` | 摘要里写了，标题没写 | 实心点或略淡 |
| `source` | 文中没有地名，按"美股市场新闻"推断为美国 | **空心点 / 半透明**，tooltip 写"来源推断" |
| `null` | 没定位到 | 不上图 |

`source` 这一类当前 20 条里约 4~5 条，**一定要区分开**：
它是推断值，如果画得和"标题明写"一样实，等于在骗用户。

### 已经修掉的一个真实错误

之前的地名词典把城市名混在国家别名里，且"谁先匹配到用谁"，导致：

> IMF-世界银行会议实际在**曼谷**，摘要里有一句
> "while China, the focus in 2018, slipped into the background"
> （中国只是背景对比），结果整条被判成**中国**。

现在改成两级词典（国家 88 条 + 城市 121 条），城市优先，
摘要里出现多个城市时宁可不打点也不猜。这类案例已固化成
`scripts/test_locate.py` 的回归用例，8 条全过。

## 本地调试

因为用了 `fetch`，直接双击打开 `index.html`（`file://` 协议）会**被浏览器拦截**，必须起一个本地服务器：

```bash
cd WorldPulse-Daily
python3 -m http.server 8000
```

然后浏览器打开 **http://localhost:8000**。

改完刷新即可看到效果。`data/news.json` 每天会自动更新，你也可以手动跑 `python3 scripts/update_news.py` 换一批最新数据来看效果。

> 调样式时建议把 `DATA_URL` 临时换成 `data/sample-news.json`：数据不变，方便反复对比前后效果，也不会因为刚好赶上 08:30 更新而"页面自己变了"。
