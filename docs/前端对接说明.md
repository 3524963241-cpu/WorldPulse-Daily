# 前端对接说明（A 同学看这里）

后端（B 同学）负责生成 `data/news.json`，前端直接 `fetch` 这个文件即可，**不需要任何后端接口、不需要 API Key**。

```js
fetch('data/news.json')
  .then(r => r.json())
  .then(data => {
    console.log(data.updated_at);  // 数据更新时间
    console.log(data.news);        // 新闻数组
  });
```

> 默认用**相对路径** `data/news.json`，这样在本地起服务器和线上 GitHub Pages 都能跑通。

## 真实数据在哪拿

数据**不用你自己抓**，后端每天都跑好了，两个地方可以拿：

| 数据源 | 地址 | 特点 |
|---|---|---|
| **线上实时数据**（推荐） | `https://3524963241-cpu.github.io/WorldPulse-Daily/data/news.json` | 真实、每天北京时间 08:30 自动更新，文件里就是真新闻。**已开启跨域**（`Access-Control-Allow-Origin: *`），任何环境都能直接 fetch |
| **仓库内数据** | `data/news.json`（clone 下来就有） | 和线上同一份，但会随每天更新而变动 |
| **固定快照** | `data/sample-news.json` | **永不变化**的一份 2026-10-13 真实数据（20 条中文），用来对照、离线调试、写死 demo 用 |

三种用法：

```js
// ① 本地 / 线上都通（默认，推荐）
const DATA_URL = 'data/news.json';

// ② 直接读线上真实数据：本地没拉仓库、或想看最新一批时用
const DATA_URL = 'https://3524963241-cpu.github.io/WorldPulse-Daily/data/news.json';

// ③ 数据固定不变，适合截图、答辩 demo、调样式时不用等接口
const DATA_URL = 'data/sample-news.json';
```

想直接看数据长什么样，浏览器打开线上地址就能看到完整 JSON，或者：

```bash
curl https://3524963241-cpu.github.io/WorldPulse-Daily/data/news.json
```

> 提醒：`file://` 协议（双击 html）下 `fetch` 依然会被浏览器拦，三种方式都得起本地服务器，这是浏览器安全限制，跟用哪个地址无关。

## 数据字段

`data/news.json` 顶层只有两个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `updated_at` | string | 数据更新时间，UTC，ISO 8601 格式，如 `2026-10-13T11:20:18Z` |
| `news` | array | 新闻数组，**已按 `heat` 从高到低排序**，**固定 20 条**（后端配额：地缘 5 / 政治 7 / 市场 8，某类不够时由其他类补位） |

`news` 数组每一项的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | **12 位十六进制字符串**（如 `46ee43f3cce0`），由 URL 哈希生成。**同一条新闻的 id 跨天不变**，可直接做列表 key、收藏、"这条昨天排第几"的对比 |
| `title` | string | 标题。翻译失败时以 `[EN]` 开头，表示这是英文原文 |
| `summary` | string | 摘要，**可能是空字符串**，前端要能处理 |
| `category` | string | 领域，三个取值，见下表 |
| `country` | string \| null | 中文国家/地区名。**未定位到时为 `null`** |
| `lat` | number \| null | 纬度。**未定位到时为 `null`** |
| `lng` | number \| null | 经度。**未定位到时为 `null`** |
| `published_at` | string | 发布时间，UTC，ISO 8601 |
| `source` | string | 来源名称，如 `NPR World`、`MarketWatch Top` |
| `url` | string | 原文链接，可直接跳转 |
| `heat` | number | 热度，**0~100 的整数**，数组已按此降序 |

> ⚠️ **别再依赖数组下标当 id 用**（比如 `news[i]` 做 DOM id）。旧版是 `news-001` 这种序号，
> 每天会指向不同新闻；现在改用 `id` 字段，跨天稳定。

## 每日概览 `data/digest.json`（F28 直接用它）

一句话说明：**当日 20 条新闻的结构化小结**，纯规则生成，每句都能点回原文核对。

```js
fetch('data/digest.json').then(r => r.json()).then(d => {
  d.top3;        // 最热三条 [{id, title, heat}]
  d.sections;    // 三个领域各一句中文小结

  // 点击小结里的标题，跳到对应新闻
  const openNews = id => { /* 用 id 在 news 数组里找 */ };
});
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | string | 概览所属日期，**北京时间**，如 `2026-10-18` |
| `updated_at` | string | 与 `news.json` 的 `updated_at` 一致，可用来校验两者是同一期 |
| `total` | number | 条目数，正常为 20 |
| `by_category` | object | 各领域条数 `{geopolitics, politics, markets}` |
| `top3` | array | 最热三条 `[{id, title, heat}]`，`title` 已去掉 `[EN]` 标记 |
| `geo` | object | `{located: 16, countries: 6, top_country: "美国"}`，`located` 是能上地图的条数 |
| `sections` | array | `[{category, count, text}]`，`text` 是**成句的中文**，可直接渲染 |

`sections[].text` 长这样：

> 地缘冲突 5 条，最受关注的是《阿尔伯塔省军事基地发生致命事件后爆发大火》（热度 91），来自 NPR World。其余报道来自 CNBC World News。

三个注意点：

1. **`text` 可能是空字符串**——某领域当天 0 条时留空，遇到空串**不要渲染那一段**（不要显示"暂无"占位，直接跳过）；
2. **不要把这段叫"AI 助手"**。它是规则生成的客观汇总，标成 AI 会让人以为能追问、能分析，反而露怯。
   写「今日概览」「数据小结」更贴合事实；
3. `top3[].title` 已经去掉 `[EN]`，但 `news[].title` 保留原样——判断翻译状态看 `news`，展示用 `digest`。

## 历史归档 `data/archive/`（F29 历史回看）

```
data/archive/
  index.json              索引，先读这个
  2026-10-18.json         那天最终 20 条
  2026-10-18-digest.json  那天的概览
  2026-10-18-pm.json      班次快照（am 早班 / pm 晚班）
```

`index.json` 结构（**按日期倒序**，最新的在前）：

```json
{
  "dates": [
    {"date": "2026-10-18", "count": 20, "generated_at": "2026-10-18T08:48:01Z", "has_digest": true},
    {"date": "2026-10-17", "count": 20, "generated_at": "2026-10-17T12:31:05Z", "has_digest": true}
  ]
}
```

用法：

```js
// 日期选择器：直接用 dates 渲染
const { dates } = await fetch('data/archive/index.json').then(r => r.json());

// 点某一天，加载那天的新闻（结构和 news.json 完全一样，只是 updated_at 是那天的时间）
const day = await fetch(`data/archive/${dates[0].date}.json`).then(r => r.json());
```

- 归档保留最近 **90 天**，更早的会被 B 自动清理；
- 归档日期按**北京时间**划分，所以 `2026-10-18.json` 指北京时间 10 月 18 日全天；
- **归档文件我这边可能还没生成**（首次部署后才开始累积）。前端要能处理「`index.json` 不存在 / `dates` 为空」的情况，
  不要写成一旦请求失败整个页面就白屏。建议 `try/catch` 后隐藏历史模块。

### `category` 三个取值

| 值 | 含义 | 建议配色 |
|---|---|---|
| `geopolitics` | 地缘冲突 | 红 |
| `politics` | 国际政治 | 蓝 |
| `markets` | 金融市场 | 绿 |

用 JS 映射成中文：

```js
const CATEGORY_LABEL = {
  geopolitics: '地缘冲突',
  politics: '国际政治',
  markets: '金融市场'
};
```

## ⚠️ 地图功能必读

**`lat` / `lng` 为 `null` 的新闻，请不要在地图上打点**，只在列表里显示。

原因是宁缺毋滥：定位不到的新闻如果随手扔个坐标上去，地图上就会出现错误的点，反而是硬伤。目前**约 20%~40% 的新闻坐标为 null**，这是正常的，不是 bug。

判断方式：

```js
news.filter(n => n.lat !== null && n.lng !== null)  // 这批才能上地图
```

另外提醒一个已知的局限：地名是靠词典匹配标题得出的，所以**多国新闻可能定位到"被提及的国家"而不是事件实际发生地**。这是两天 MVP 工期内的折中，答辩时如果被问到，如实说明即可。

## 本地调试

因为用了 `fetch`，直接双击打开 `index.html`（`file://` 协议）会**被浏览器拦截**，必须起一个本地服务器：

```bash
cd WorldPulse-Daily
python3 -m http.server 8000
```

然后浏览器打开 **http://localhost:8000**。

改完刷新即可看到效果。`data/news.json` 每天会自动更新，你也可以手动跑 `python3 scripts/update_news.py` 换一批最新数据来看效果。

> 调样式时建议把 `DATA_URL` 临时换成 `data/sample-news.json`：数据不变，方便反复对比前后效果，也不会因为刚好赶上 08:30 更新而"页面自己变了"。
